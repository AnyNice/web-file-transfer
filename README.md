# 局域网快传 · web-file-transfer

基于 Next.js 的局域网文件传输工具，两种模式：

- **服务器模式**：文件上传到主机 `uploads/` 目录保存，可再下载/删除；支持文件夹上传（保留目录结构）、文件夹打包下载（流式 ZIP + ZIP64，边打边传不占内存）、大文件流式上传下载、Range 分段下载。
- **P2P 模式**：浏览器之间 WebRTC 直传（64KB 分块 + 应用层流控——接收方按已落盘字节回执、发送方未被确认的在途量不超过 4MB，手机等慢速接收端不会被冲断连接；接收端流式写入 OPFS 暂存，不占内存），服务器只做邀请码信令，不经手文件内容；文件夹发送保留相对路径。接收保存一律走**浏览器原生下载**：每个文件接收完成即自动下载到浏览器下载目录（文件夹内文件拍平文件名、同名自动加 `_1`、`_2` 后缀）。STUN 服务器含国内可达节点（小米 / 腾讯 / Cloudflare），提升复杂网络下的直连打通率。

## 运行

```bash
npm install
npm run build
npm run start        # 默认端口 3000，局域网用 http://<主机IP>:3000 访问
```

开发：`npm run dev`

## 访问口令

所有接口都需要口令登录。口令来源（优先级从高到低）：

1. 环境变量 `ACCESS_CODE`
2. `data/access-code.txt`（首次打开页面时自动生成 6 位数字，主机上打开这个文件即可看到；想改口令直接改文件内容后重启服务）

邀请码（P2P）：6 位数字，房间有效期 10 分钟，信令状态保存在 `p2p-rooms.json`。每个浏览器有独立身份（localStorage 中的 clientId），建房时登记、入房时比对——同一个浏览器不能拿自己生成的邀请码连接自己（会提示「不能连接自己」）；换一个浏览器或设备不受影响。

登录后顶栏可查看当前口令（大字显示 + 一键复制），以及局域网地址二维码（服务器动态列出全部可用地址，含 Tailscale 地址，多地址可切换），扫码即可在其他设备打开。

## 运行日志

- 位置：项目 `logs/` 目录，按天一个文件 `app-YYYY-MM-DD.log`，保留 14 天自动清理。
- 内容：登录成功/失败、上传完成/失败、删除、文件夹打包下载、P2P 建房/配对/无效码/自连拒绝等；前端 P2P 断开与传输失败也会回传落盘（行首带时间、级别、模块标签，前端回传的标签带 `client:` 前缀）。
- 查看：登录后点页面顶栏「日志」可看今日最近 200 条或下载整天日志；也可直接打开 `logs/` 里的文件。接口为 `GET /api/logs`（需登录）。

## 管理员与中转目录

服务器中转的文件默认存放在项目 `uploads/` 目录。管理员可以改到任意绝对路径（如另一块盘）：

- 点页面顶栏「管理」，输入**管理员口令**（与访问口令不同：环境变量 `ADMIN_CODE`，未设置时自动生成 8 位数字存放在 `data/admin-code.txt`，主机上打开查看）。
- 设置保存到 `data/settings.json`，即时生效、无需重启；新目录不存在会自动创建，保存前会校验可写。
- 切换只改变后续文件的落点，**旧目录里的文件不会自动搬过去**，文件列表将显示新目录的内容；可随时一键恢复默认。
- 文件区右上角可在「列表 / 卡片」两种显示间切换（默认列表），偏好记在浏览器本地。
- 文件区支持多选：勾选框 / 全选（当前目录），可一键打包下载为一个 ZIP 或批量删除。
- 下载文件时页面左下角浮窗会给反馈：进度、速度，以及完成 / 已开始 / 失败提示。

## 可选环境变量

- `ACCESS_CODE`：固定访问口令
- `ADMIN_CODE`：固定管理员口令
- `MAX_UPLOAD_MB`：单个上传文件上限（MB），0 或不设置 = 不限制

## 2026-11-12 大修记录

- 上传：重写流式 multipart 解析。旧实现不剥离结尾 boundary、按文本拼接 header，每个上传文件都会被污染损坏（实测 256B → 310B）；新实现全程 Buffer 状态机、边收边写临时文件、成功才转正，大小与文件无关。
- 下载：接口支持 Range + catch-all 多级路径；前端优先 File System Access 流式写盘，否则浏览器原生下载，均不再把整个文件以 Blob 拉进内存（旧版大文件直接卡死标签页）。
- P2P 传输层重写：分块 2MB → 64KB 并加 bufferedAmount 背压；接收端流式落盘 OPFS（旧版全内存拼 Blob）；删除「接收方 2 秒后关 ctrl 通道」、假 ICE 重启等逻辑；心跳改为 ping/pong 双向校验；0 字节文件可正常完成。
- 信令：房间创建即落盘、按房间 10 分钟 TTL（旧版只存内存、30 秒且过期判断错误）、邀请码查重、猜码限速。
- 安全：全接口加口令鉴权（旧版任何人可列目录/下载/删除，已实测）；登录与猜码均有限速；路径穿越校验收敛到统一 helper。
- 前端：修复拖拽上传的异步竞态丢文件与重复入队；文件夹上传保留目录结构；文件列表支持目录树与删除。
- 工程：Tailwind / Font Awesome 改本地打包（原先 CDN，无外网局域网直接没样式）；删除死代码 ServerPanel/Tooltip；`.gitignore` 补 uploads/、data/、p2p-rooms.json。

## 已知限制

- **iPhone Safari 的 P2P 直连**：iOS 的「本地网络」隐私权限会拦截 WebRTC 的局域网地址解析。使用前请在 iPhone 上打开 设置 → 隐私与安全性 → 本地网络 → Safari，并关闭当前 Wi-Fi 的「限制 IP 地址跟踪」；否则会出现信令配对成功、但连接始终建不起来。服务器中转模式不受此影响。
- 局域网走 HTTP（非安全上下文），浏览器不提供文件 / 目录选择器，页面所有保存都走浏览器原生下载，各端行为一致。
- 未配置开机自启：主机重启后需在项目目录手动 `npm run start` 拉起服务。
